# Day 2 デザインルール

## コンセプト

ネイビーを基調とした信頼感に、青緑、角丸、十分な余白を加え、「堅実さ」と「相談しやすさ」の中間を表現する。派手な装飾より、情報の読みやすさと操作の見つけやすさを優先する。

## カラー

要件定義書の初期カラーコードを正式なデザイントークンとして採用する。

| トークン予定名 | 値 | 用途 |
|---|---|---|
| `$color-primary` | `#15324B` | 見出し、主要なブランド表現 |
| `$color-accent` | `#0F8B8D` | 装飾、アイコン、強調 |
| `$color-accent-dark` | `#0B6E70` | 白文字を載せるCTA、濃色アクセント |
| `$color-text` | `#1D2A33` | 本文 |
| `$color-background` | `#F5F8F8` | セクション背景 |
| `$color-border` | `#D9E3E6` | 境界線 |
| `$color-white` | `#FFFFFF` | 白背景、反転文字 |

### 使用規則

- 通常本文は白またはライトグレー背景にダークグレーを使用する。
- 白文字の主要CTAは濃い青緑を背景に使用する。
- 通常の青緑は装飾と大きな文字を中心にし、小さい白文字の背景には使用しない。
- エラー、成功などの状態色はフォーム実装時にコントラストを確認して追加する。色だけで状態を伝えない。

## タイポグラフィ

```text
font-family:
  "Noto Sans JP",
  "Hiragino Kaku Gothic ProN",
  "Yu Gothic",
  sans-serif
```

| 用途 | モバイル | PC | 太さ | 行間 |
|---|---:|---:|---:|---:|
| ページの主見出し | 32px | 48px | 700 | 1.3 |
| セクション見出し | 28px | 40px | 700 | 1.4 |
| 小見出し | 20px | 24px | 700 | 1.5 |
| 本文 | 16px | 16px | 400 | 1.8 |
| 補足 | 14px | 14px | 400 | 1.7 |

- 文字サイズは固定値へ依存しすぎないよう、実装時は`rem`へ変換する。
- 見出し階層は視覚サイズではなくHTMLの文書構造に合わせる。
- 長文本文は1行おおむね40文字前後を目安に最大幅を設定する。

## 余白

8pxを基準に、次のスケールを採用する。

| トークン予定名 | 値 |
|---|---:|
| `$space-1` | 4px |
| `$space-2` | 8px |
| `$space-3` | 12px |
| `$space-4` | 16px |
| `$space-5` | 20px |
| `$space-6` | 24px |
| `$space-8` | 32px |
| `$space-10` | 40px |
| `$space-12` | 48px |
| `$space-16` | 64px |
| `$space-20` | 80px |
| `$space-24` | 96px |

- コンテンツ左右余白：スマートフォン20px、タブレット32px、PC48〜64px。
- セクション上下余白：スマートフォン64px、PC96pxを基本とする。
- カード内余白：24pxを基本とする。
- コンテンツ最大幅：1200px。

## レスポンシブ基準

モバイルファーストで、内容に応じて次の基準を使用する。

| 名前 | 開始幅 | 主な変化 |
|---|---:|---|
| Mobile | 0px | 1カラム、ハンバーガーメニュー |
| Tablet | 768px | 左右余白32px、必要に応じて2カラム |
| Desktop | 1024px | PCナビゲーション、3〜4カラム |
| Wide | 1440px | 最大幅1200px内で左右余白を確保 |

中間幅で内容が窮屈になる場合は、要素単位で折り返しを優先し、固定幅は設けない。

## 角丸と影

| 用途 | 角丸 | 影 |
|---|---:|---|
| ボタン、入力欄 | 8px | 原則なし |
| カード | 16px | `0 8px 24px rgb(21 50 75 / 8%)` |
| 小さなタグ | 999px | なし |
| ヘッダー（スクロール後） | 0px | `0 4px 16px rgb(21 50 75 / 8%)` |

- カードは境界線と背景色を併用し、影だけで領域を区別しない。
- 入力欄のエラー状態も境界線、文言、関連付けを併用する。

## ボタン

### 種類

| 種類 | 用途 | 外観 |
|---|---|---|
| Primary | 主要CTA、次の段階 | 濃い青緑背景＋白文字 |
| Secondary | 一覧遷移、補助動作 | 白背景＋ネイビー枠 |
| Text link | 文中・補助遷移 | 下線または明確なリンク表現 |

### 共通規則

- 最小操作領域は44px四方を目安とする。
- ラベルは動詞を含む具体的な文言にする。
- `hover`だけでなく`focus-visible`を同等以上に明示する。
- 無効状態は色だけでなく`disabled`属性と文言の状態で示す。
- リンクは遷移、ボタンは開閉・送信段階などの操作に使い分ける。

## カード

- 基本構造：アイコンまたは画像 → 補助情報 → 見出し → 説明 → 必要な場合のみリンク。
- 全体クリックを採用する場合も、リンク先を持つカードだけに限定する。
- 詳細ページのない導入事例とお知らせには、矢印、ホバー浮上、ポインターカーソルを付けない。
- 同一グリッド内では見出し位置と内余白をそろえる。

## 見出し

- セクション見出しは日本語見出しを主体とし、装飾は短い線または小さなアクセントに限定する。
- 見出し直後に必要なら1〜2文の導入文を置く。
- 色やサイズだけに依存せず、HTMLの`h1`〜`h3`を順序どおり使用する。
- 1ページの`h1`は1つを基本とする。

## パンくず

- 404を除く下層ページに配置する。
- 順序付きリストで「トップ > 現在のページ」を表す。
- 現在ページはリンクにせず、`aria-current="page"`を付ける。
- 区切り記号は装飾として読み上げ対象から外す。
- モバイルで長くなる場合は折り返しを許容し、横スクロールさせない。

## フォーム

- ラベルを入力欄の上に常時表示する。
- 必須／任意を文字で併記する。
- 説明、入力欄、エラー文の順に配置する。
- エラー文は項目直下に置き、入力欄と`aria-describedby`で関連付ける。
- ボタンはモバイルで縦並び、確認画面のPC表示では「戻る」「送信」の順を保った横並びを許容する。

## フォーカスと動き

- `focus-visible`は2px以上の輪郭と十分なオフセットで表示する。
- セクション表示は短く控えめなフェードに限定する。
- `prefers-reduced-motion: reduce`では移動を伴う演出を停止または即時表示にする。
- メニューやFAQの状態は視覚表現とARIA属性を同期させる。
