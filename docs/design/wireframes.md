# Day 2 ワイヤーフレーム

## 前提

- モバイルファーストで設計する。
- コンテンツの並び順は要件定義書を変更しない。
- 主要CTA「ITのお悩みを相談する」をヘッダー、ファーストビュー、ページ末尾で見つけられるようにする。
- ワイヤーフレームは情報構造と優先順位を示す。原稿と素材はDay 3、HTML実装はDay 4以降に行う。

### スマートフォンでの優先順位

1. ファーストビューでは文章を先、イラストを後に配置する。
2. すべてのカードを1カラムとし、横スクロールを前提にしない。
3. 固定CTAは初期非表示とし、フッター付近ではコンテンツを隠さない。
4. ハンバーガーメニュー内はグローバルナビゲーション5項目と主要CTAを縦並びにする。

### PCでのレイアウト規則

- ファーストビューは文章とSVGをおおむね1:1の2カラムとする。
- 3項目・3カードは3カラム、導入フローは4カラムを基本とする。
- FAQは読みやすい本文幅に抑え、横2列にはしない。
- お知らせは日付、カテゴリ、タイトルの位置をそろえる。

### ページ別の固有領域

| ページ | 固有コンテンツの順序 |
|---|---|
| サービス | 全体説明 → 3サービス詳細 → 導入の流れ → FAQまたは注意事項 |
| 導入事例一覧 | 架空事例の注記 → 事例カード3件 |
| 製造業事例詳細 | 架空事例の注記 → 企業概要 → 課題 → 提案 → 導入の流れ → 変化 → コメント → 関連サービス |
| お知らせ一覧 | お知らせ3件。詳細リンク、矢印、リンク用ホバー表現は付けない |
| 会社案内 | 会社紹介 → 理念 → 代表メッセージ → 会社概要 → 対応地域 |
| お問い合わせ | デモ注記 → 進捗表示 → 入力／確認／完了の表示領域 |
| プライバシー | 利用目的 → 管理 → 第三者提供 → アクセス解析 → 窓口 → 制定日 |

## お問い合わせフォーム：3段階

3画面とも同一URL、同一ページ内で表示状態を切り替える。

### 1. 入力

```text
[入力] ─ 確認 ─ 完了

エラー概要（エラー時のみ・aria-live）

会社名                     任意
[                              ]
氏名                       必須
[                              ]
メールアドレス              必須
[                              ]
電話番号                    任意
[                              ]
相談したいサービス          必須
[ 選択してください            v]
相談内容                    必須
[                              ]
[                              ]
希望する連絡方法             任意
( ) メール ( ) 電話 ( ) 指定なし
[ ] 個人情報の取り扱いに同意  必須

[入力内容を確認する]
```

- エラーは該当項目の直下へ表示する。
- エラー概要から最初のエラー項目へフォーカスを移す。
- 必須／任意を文字で明示する。

### 2. 確認

```text
入力 ─ [確認] ─ 完了

会社名                  入力値
氏名                    入力値
メールアドレス           入力値
電話番号                 入力値
相談したいサービス       入力値
相談内容                 入力値
希望する連絡方法          入力値
個人情報の取り扱い        同意済み

[入力画面へ戻る] [送信する（デモ）]
```

- 戻る操作後も入力内容を保持する。
- 実送信されないことをボタン付近でも再確認できるようにする。

### 3. 完了

```text
入力 ─ 確認 ─ [完了]

お問い合わせありがとうございます
入力内容は実際には送信されていません。

[トップページへ戻る]
```

- 完了見出しへフォーカスを移し、状態変更を通知する。
- 入力値を外部へ送信・保存しない。
